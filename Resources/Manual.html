Convertify Manual

Convertify converts audio and video files from the Finder. Right-click a file, choose a conversion from the Services menu, and a window shows the progress. It was built for use with VoiceOver, so everything in it can be read and operated from the keyboard.

Origins and credits

Convertify is the Mac descendant of SendTo encoders, a Windows project started by Andre Louis (github.com/OnjLouis, known as Onj) and further developed by arfy from 2012 on, and still maintained by Andre in 2026. Their idea was simple and good: put encoders such as LAME, FLAC, oggenc and Opus in the Windows "Send To" menu, so a blind user could convert a file with a couple of keystrokes and no fiddling with command lines. That project is the reason this one exists, and the conversions here follow the same names and the same quality settings wherever that made sense. Several ideas in this version, such as copying video streams without re-encoding, extracting audio losslessly, the MKV and image conversions, the media report and the output naming scheme, were adopted from Andre's September 2026 release, and the update mechanism is based on his Clipman app.

The Mac version was made by Jakob Rosin in 2026, first as a set of scripts and later as this app, written together with Claude, an AI assistant from Anthropic. The source code and new versions live at github.com/jakobrosin/convertify.

The actual encoding is done by FFmpeg, the FLAC tools and vorbis-tools from the Xiph.Org Foundation, and the LAME, Opus and x264 libraries. See the licences section at the end.

What you need

  • A Mac with Apple Silicon (M1 or later).
  • macOS 14 Sonoma or newer.
  • Nothing else. All the conversion tools are inside the app.

Installing

  1. Open the disk image and drag Convertify to your Applications folder.
  2. Open Convertify once. macOS will say that it cannot verify the developer and refuse to open it. This is normal for an app that is not distributed through Apple.
  3. Open System Settings, go to Privacy and Security, scroll to the bottom of the page, and press Open Anyway next to the message about Convertify. Confirm with your password or Touch ID.
  4. Convertify opens with an empty window. You can close it. The conversions are now in the Finder Services menu.

If the Services menu does not show them right away, log out and back in. macOS sometimes needs that to notice a new app's services.

Starting a conversion

From the Finder, the usual way

  1. Select one or more audio or video files in the Finder.
  2. Open the context menu. With VoiceOver that is VO Shift M; with a mouse, right-click.
  3. Open the Services submenu. The conversions are under the "Files and Folders" heading.
  4. Choose one, for example MP3 Encode.

Convertify opens in front, shows the progress, plays a sound when it is finished, and quits by itself a few seconds later. If anything fails, the window stays open so you can read what went wrong.

The same Services submenu is also in the application menu of the Finder (the menu named Finder in the menu bar), which is sometimes easier to reach with the keyboard.

From inside Convertify

  • The Convert menu lists every conversion. Choosing one opens a file chooser, and the job starts when you confirm.
  • File, Open Files (Command O) lets you pick files first and then asks which conversion to run.

By dropping files

Drop files on the Convertify icon in the Dock or in the Applications folder. Convertify asks which conversion to run.

Several files at once

All conversions accept several files. They are processed one after the other, and each file gets its own row in the window. Folders are skipped with a note.

The conversions

Every conversion accepts any audio or video file that FFmpeg can read, which is nearly everything: WAV, AIFF, FLAC, MP3, AAC and M4A, Opus, OGG, ALAC, WMA, video files, and more. Title, artist and album tags are carried over where the output format can hold them.

MP3 Encode

Makes an MP3 with the LAME encoder at variable bitrate quality 2, around 190 kbit/s. This is the same setting the Windows project used and is transparent for most listening.

MP3 Encode (Low Quality)

Makes a small MP3 at a constant 64 kbit/s. Good for speech, podcasts and anything where size matters more than fidelity.

AAC Encode

Makes an M4A file with AAC audio at 128 kbit/s, using Apple's own AAC encoder built into macOS. Plays everywhere Apple devices play.

Opus Encode

Makes an Opus file at 96 kbit/s variable bitrate, the same default the opusenc tool uses for stereo. Opus gives the best quality per kilobit of all the lossy formats here.

OGG Encode

Makes an Ogg Vorbis file at quality 4, around 128 kbit/s, the same setting as the Windows project.

File to Wav

Decodes any file to a plain WAV. The bit depth follows the source: 16-bit sources give 16-bit WAV, 24-bit sources give 24-bit, 32-bit float stays float. Lossy sources such as MP3 come out as 16-bit.

Flac to Wav and Delete

Decodes a FLAC file to WAV with the official FLAC tool and then deletes the FLAC file. If the FLAC was made from a WAV or AIFF with its extra metadata kept, that metadata is restored. The original is only deleted after the WAV was written successfully.

Wav to Flac and Delete

Compresses a WAV or AIFF to FLAC at the highest compression level, verifies the result by decoding it again, and then deletes the WAV file. 32-bit float files, which FLAC cannot store, are converted to 24-bit first. The original is only deleted after the verification passed.

File to MP4

Puts a video into an MP4 container. If the video stream is something MP4 can hold, such as H.264 or HEVC, it is copied as it is, which takes seconds and loses nothing; only audio that MP4 cannot hold, such as uncompressed PCM, is re-encoded to AAC at 192 kbit/s. If the video itself has to be re-encoded, Convertify uses the Mac's hardware H.264 encoder first and the software x264 encoder as a fallback. Only offered for video files.

File to MOV

The same as File to MP4, but for a QuickTime MOV container, which can also hold ProRes video and uncompressed audio unchanged.

File to MKV

Repackages a media file into a Matroska container without re-encoding anything. All streams, chapters and metadata that Matroska supports are kept. Useful for files whose original container is awkward, or for keeping several audio tracks and subtitles together.

Extract Audio

Takes the first audio stream out of a video or audio file without re-encoding it, and gives the result the right extension for what it is: m4a for AAC or Apple Lossless, mp3, opus, ogg for Vorbis, flac, wav for uncompressed audio, and mka as a fallback for unusual codecs. Metadata and chapters are kept where the container allows. This is the way to get the sound out of a video with no quality loss.

Image to JPEG and Image to PNG

Convert pictures with the image tools built into macOS. JPEG output uses quality 90. Photo metadata that the destination format can hold is kept. HEIC photos from an iPhone can be converted this way. Only offered for image files.

Media Info

Not a conversion but a report: container, duration, size, bitrate, each video and audio stream with its codec, resolution or sample rate, channels and bit depth, then the tags and the number of chapters. It opens in its own window as plain text that VoiceOver reads line by line and that you can select and copy. Also available for the selected row in the Files table with Command Shift I, showing both the source and the output.

Image + Audio to Video

Select exactly one picture and one audio file. The result is an MP4 video showing the picture for the whole length of the audio, the way people upload audio to video sites. The picture is fitted into 1280 by 720 pixels without stretching. The audio is copied if it is already AAC or MP3, otherwise it becomes AAC.

How output files are named

  • The output goes next to the input, with the same name and the new extension. "Song.flac" becomes "Song.mp3".
  • Convertify never overwrites a file. If "Song.mp3" already exists, the new file is called "Song-converted.mp3", then "Song-converted-2.mp3", "Song-converted-3.mp3" and so on. This is the same scheme the Windows SendTo encoders use.
  • Converting a file to its own format, such as an MP3 to MP3, also gives "Song-converted.mp3".
  • Every result is read back with ffprobe before it counts as done. A file that cannot be read back is deleted and reported as failed, so a broken output never sits next to a good original.
  • Only the two conversions with "and Delete" in their name remove anything, and only their own input file.

The Convertify window

From top to bottom the window contains:

  • A status line for the file being converted, for example "Converting Song.flac, 47 percent, about 2 minutes left".
  • A progress bar for the current file. VoiceOver reads its percentage.
  • The Files table. One row per file, newest at the top. Keyboard focus lands here when the window opens. Each row reads in this order: file name, status, progress, time started, conversion, result. The status is one of waiting, converting, done, failed, skipped or cancelled. For a finished file the progress column says how long it took, and the result column holds the name of the output file or the reason for the failure.
  • Buttons: Cancel All, Clear History and Close.

The window title also carries the file name and the percentage, so switching to Convertify with Command Tab already tells you how far it is.

Moving around the table

  • Up and Down arrows move one row.
  • Home and End jump to the first and last row.
  • Page Up and Page Down move a screenful.
  • Return opens the output file of the selected row in its default app.
  • Delete removes the selected finished rows from the history. The files on disk are not touched.
  • Escape hides the window. The app keeps running, and a running job continues.
  • Command A selects all rows, so Command A then Delete empties the history. Shift with the arrow keys extends the selection.

Menus and keyboard shortcuts

Convertify menu

  • About Convertify. Shows the version and where the tools, the log and the history live.
  • Check for Updates and Version History. See the section on updating below.
  • Preferences, Command Comma.
  • Quit, Command Q. If a conversion is running you are asked first.

File menu

  • Open Files, Command O. Choose files, then the conversion.
  • Reveal Output in Finder, Command R.
  • Open Output, Command Down arrow.
  • Reveal Source in Finder, Command Shift R.
  • Retry This File, Command T. Runs the same conversion on the selected row's source file again.
  • Show Details, Command D. Opens a sheet with everything about the selected row: full paths, times, the complete error message. The text can be selected, and a Copy button puts it all on the clipboard.
  • Close Window, Command W. If nothing is running and "keep the window open" is off, this quits the app.

Edit menu

  • Copy, Command C. Copies the selected rows as sentences, one per line, handy for pasting an error into a message.
  • Select All, Command A.
  • Remove from History, Delete. Works on all selected rows.
  • Clear History, Command Shift Delete. Asks first unless you turn that off in Preferences.

Convert menu

One item per conversion, grouped: lossy formats, then WAV and Extract Audio, then the video conversions, then the image conversions, and the two "and Delete" conversions last. Media Info is at the bottom. Each opens a file chooser.

Job menu

  • Cancel This File, Command Period. Stops the current file, deletes its partial output, and goes on with the next one.
  • Cancel All, Command Shift Period.

Window and Help menus

  • Show Convertify Window, Command 0.
  • Speak Status, Command I. VoiceOver announces the current progress, or the last result when nothing is running, without moving your cursor.
  • Convertify Help shows a short summary. Convertify Manual opens this document.
  • Open Log File and Show History File in Finder.

Context menu on a row

Right-click a row, or with VoiceOver press VO Shift M on it, for Open Output, Reveal Output, Reveal Source, Retry, Copy Row and Remove from History.

Preferences

Open with Command Comma. Two tabs, General and History. Changes take effect immediately.

General

  • Keep the window open after jobs finish. Off by default: the app quits by itself after a successful job.
  • After a successful job, quit after. A choice of 3, 6, 10, 15 or 30 seconds. Six by default.
  • Bring the window to the front when a job starts. On by default. Turn it off if you prefer the window to appear without taking your keyboard focus; you can still reach it with Command Tab.
  • Show a notification when a job finishes.
  • Play a sound when a job finishes. Glass for success, Sosumi for failure.
  • Check for updates once a day when Convertify starts. On by default.
  • Install updates without asking. Off by default.

History

  • Keep at most. 25, 50, 100 or 200 finished files, or no limit. Fifty by default.
  • Drop old entries. Never, or after 7, 30 or 90 days.
  • Ask before clearing the history.
  • Clear the history when Convertify quits. Off by default. With it on, the table is empty on every launch and only shows the current job.

Whatever the settings, the window always stays open when a file has failed.

Notifications and sounds

When a job ends you get a notification with the name of the conversion and either "Done" with the output name, or the number of failed files and the first reason. VoiceOver reads it. Because the app is not signed by Apple, macOS does not let it send notifications directly, so they arrive through the system's script notification channel and show the Script Editor icon. That is expected.

There are no notifications or announcements while a job is running. Open the window when you want to know how far it is.

The history

Finished, failed, skipped and cancelled files stay in the table so you can find results later. The list is saved between launches in a small file in your Library folder. Trim it with the Delete key, the Clear History button, or the automatic limits in Preferences. Clearing the history never deletes any converted file.

If something does not work

The conversions are not in the Services menu

  • Make sure Convertify has been opened at least once after installing.
  • Log out and back in. Finder caches the Services menu.
  • Check that the entries are enabled: System Settings, Keyboard, Keyboard Shortcuts, Services. They are under Files and Folders.
  • Only conversions that fit the selected file are shown. File to MP4 and File to MOV appear only for videos, and Image + Audio to Video needs a picture or a sound file.

"Encode Selected Audio Files" only offers AAC

That entry is Apple's own built-in service, not part of Convertify. Ignore it, or turn it off in the same Services settings.

macOS asks whether Convertify may access a folder

The first time Convertify reads a file in Downloads, Desktop, Documents or a cloud folder, macOS asks for permission. Allow it, once per folder.

A file failed

Read the result column of its row, or copy the row with Command C. The most common reasons: the file is not a media file, it is damaged, or a video conversion was attempted on an audio-only file. More detail is in the log, reachable from the Help menu.

Convertify quit while a conversion was running

Check that "keep the window open" behaves as you expect and that you did not press Command Q. A cancelled or interrupted conversion always deletes its partial output, so there are no half files left behind.

Updating Convertify

When a newer Convertify is installed over an older one, whether by dragging a new copy into Applications or through Check for Updates, the app tidies up after itself on the next launch: it re-registers its Finder services, removes its old temporary files, and looks for stray copies of itself. If a second copy is found in Downloads or elsewhere, it offers to move that copy to the Trash, because macOS may otherwise register the Finder services from the wrong one. If you happen to run Convertify straight from the disk image or from Downloads, it offers to install itself into Applications and relaunch from there.

Check for Updates, in the Convertify menu, asks a small update file on the web whether a newer version exists. If so, it shows what is new and offers Download and Install. The download is checked against its published size and checksum before anything is touched, then the copy in Applications is replaced in place and Convertify relaunches. Nothing else is written anywhere. The person who gave you Convertify can tell you the address of the update file; without one, Check for Updates simply says so.

Privacy

Convertify connects to the internet only to check for updates, once a day at launch if that is enabled and when you ask, and then only to GitHub, to read the release list and, if you agree, download the new version. It sends nothing anywhere and collects nothing. The only things it writes are the converted files next to your originals, a log file and a history file in your own Library folder, and its preferences.
